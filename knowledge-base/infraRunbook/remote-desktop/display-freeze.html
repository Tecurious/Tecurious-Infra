saiserver · ASUS TUF FX505DT · 28 Sep 2026

Why the screen stays black

The desktop program (Xorg) freezes when the ultrawide is plugged in at boot. When the desktop freezes, the monitor, the laptop screen and Screen Sharing from the Mac all stop working together.

The laptop has two graphics chips

AMD Radeon Vega (built in)Wired to the laptop's own screen.driver: amdgpu · full display support
NVIDIA GTX 1650The HDMI port is wired to this chip only.driver: 595-server headless · compute only, no display part

Booting with the ultrawide plugged in

what broke
  1. Xorg sees the ultrawide on HDMI, which belongs to the NVIDIA chip.
  2. The NVIDIA driver has no display part, so Xorg uses a workaround: AMD draws every frame and copies it to NVIDIA to send out.
  3. About 30 seconds after boot, that workaround freezes Xorg. The log's last line each time was randr: falling back to unsynchronized pixmap sharing.
  4. With no desktop, x11vnc never starts, so Screen Sharing on the Mac has nothing to connect to.

Booting with the ultrawide unplugged

working now

Xorg only uses the AMD chip, so the workaround never runs. The desktop starts, x11vnc starts on port 5900, and the Mac connects with open vnc://<server-tailscale-ipv4>:5900.

The fix: install the full NVIDIA driver

next step

The full driver has the display part, so the NVIDIA chip sends the picture to HDMI directly and the copy workaround is gone. It's the same 595 version, so CUDA and Ollama keep working. The desktop uses about 200–300 MB of the GTX 1650's 4 GB.

sudo apt install nvidia-driver-595-server

After it installs, NVIDIA gets set as the main graphics chip, and then you reboot with the ultrawide plugged in.
